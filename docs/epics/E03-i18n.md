# E03 · Internationalization (EN / LT)

**Goal:** The whole UI is available in English and Lithuanian, with locale-aware dates, numbers and plurals.
**Milestone:** M1 · Walking skeleton
**Depends on:** E01

---

### E03-T01 · next-intl setup & locale routing — `M`
**Why:** All features need a translation mechanism from day one; adding it later means rewriting every screen.

**Scope**
- Install `next-intl`; routes under `app/[locale]/…` with locales `en` and `lt`, default `lt`.
- Middleware that combines next-intl locale detection with Clerk's auth middleware (one `middleware.ts`).
- Locale chosen in this order: URL → `NEXT_LOCALE` cookie → saved profile locale → `Accept-Language` → `lt`.
- `messages/en.json` and `messages/lt.json` with namespaces per feature (`common`, `nav`, `auth`, `buddies`, `sessions`, `exercises`, `logging`, `progress`, `settings`, `errors`).
- TypeScript type-safe message keys (`global.d.ts` augmentation).
- `<html lang>` set to the active locale; localized `<title>` and meta description.

**Out of scope:** Language switcher UI (E03-T02); formatting helpers (E03-T03).

**Done (E03-T01):** `next-intl` 4.14.9 with `src/proxy.ts` (Next.js 16 renamed `middleware.ts` to `proxy.ts`; the next-intl handler sits in a `proxy()` function that Clerk's `clerkMiddleware` wraps in E04-T01, see the `TODO(E04-T01)` there). Routing config in `src/lib/i18n/routing.ts` (locales `lt` / `en`, default `lt`, prefix always shown, `NEXT_LOCALE` cookie kept for a year); request config in `src/lib/i18n/request.ts`, which reads the locale from the `[locale]` **root param** (`next/root-params`) because next-intl deprecated `setRequestLocale` in its favor; pages stay statically rendered and no longer take `params` for the locale. `app/[locale]/layout.tsx` is now a root layout (`<html lang>`, localized title template and meta description, `NextIntlClientProvider`); the unlocalized `/dev` and `/debug` pages moved into `app/(developer-tools)/` with their own English root layout; both share `app/root-document.tsx`. Unknown paths under a locale render the localized `[locale]/not-found.tsx` through `[locale]/[...unknownPath]`. Message keys are type-checked through the `AppConfig` augmentation in `src/global.d.ts` (`src/lib/i18n/__typetests__/message-keys.typetest.tsx`). New namespaces `auth`, `exercises`, `logging` (and `landing`) hold a minimal first set of strings. The interim `use-translations.ts` / `locale-param.ts` helpers are gone. `ThemeToggle` and `NumberStepper` (default locale) use next-intl; `UI_LABELS` stays English until E03-T03 (it needs plurals); `global-error.tsx` stays English (`TODO(E03)`: no provider above it). Deviations: the "saved profile locale" step is a `TODO(E04-T04)` in the proxy (the cookie carries it once E03-T02 / E04-T04 write it), and "protected routes still require sign-in under both locales" waits for Clerk (E04-T01). An unknown first segment is redirected to a locale first (`/de/dashboard` → `/lt/de/dashboard`, then 404).

**Acceptance criteria**
- [ ] Opening `/` with a Lithuanian browser redirects to `/lt`; with an English browser to `/en`; otherwise to `/lt`.
- [ ] Server Components (`getTranslations`) and client components (`useTranslations`) both render translated text.
- [ ] Using a key that doesn't exist fails `typecheck`.
- [ ] `<html lang>` is `lt` or `en` to match the URL.
- [ ] Protected routes still require sign-in under both locales.

**Depends on:** E01-T01

### E03-T02 · Language switcher & persistence — `S`
**Why:** Users must be able to change language at any time, and their choice should follow them across devices.

**Scope**
- `LanguageSwitcher` (LT / EN, shown with native names "Lietuvių" / "English") in the avatar menu and on the landing page.
- Switching replaces the locale in the current URL, keeping path and query params.
- Saves to the `NEXT_LOCALE` cookie; when signed in, also updates `profiles.locale` via Server Action.
- On sign-in, if `profiles.locale` differs from the URL, redirect to the saved locale.

**Out of scope:** Translating user-created content.

**Already in place (E03-T01):** the avatar menu's language radio items (`AccountMenu`) switch with `router.replace(getLocalizedPathname(pathname, locale))` and drop the query string (`TODO(E03-T02)`). next-intl's locale-aware navigation (`createNavigation(routing)` from `next-intl/navigation`, giving `useRouter().replace(pathname, { locale })`, `usePathname()` without the locale, `Link`) is not set up yet; create it as `src/lib/i18n/navigation.ts` from `routing` and use it for the switcher (it keeps the path; pass the current `useSearchParams()` to keep the query). The proxy only rewrites `NEXT_LOCALE` on document requests (`Sec-Fetch-Dest: document`), so a soft-navigation switch must set the cookie on the client (next-intl's `useRouter` does) or in the Server Action; name and max age are `LOCALE_COOKIE_NAME` / `LOCALE_COOKIE_MAX_AGE_SECONDS` in `src/lib/i18n/locales.ts`. The landing page (`app/[locale]/(public)/page.tsx`) has a comment where the switcher goes. Clerk's `localization` is E04-T01's.

**Acceptance criteria**
- [ ] Switching on `/lt/sessions/123?tab=x` leads to `/en/sessions/123?tab=x`.
- [ ] After switching to EN on phone, signing in on desktop opens the app in EN.
- [ ] Switching is keyboard accessible and the current language is indicated.
- [ ] Clerk components (sign-in, user menu) switch language too.

**Depends on:** E03-T01, E04-T04

### E03-T03 · Formatting helpers — `S`
**Why:** Dates, numbers and plurals look different in Lithuanian and English; wrong formats feel broken to users.

**Scope**
- `useFormat()` / `getFormat()` wrapping next-intl formatters with presets:
  - `weight(57.5)` → "57,5 kg" (LT) / "57.5 kg" (EN)
  - `date(d)`, `dateTime(d)`, `relative(d)` ("prieš 2 dienas" / "2 days ago")
  - `duration(minutes)` → "1 val. 15 min." / "1 h 15 min"
- ICU plural messages for common counts (sets, reps, sessions, exercises, buddies), using Lithuanian forms one / few / many / other.
- Times shown in the user's browser timezone; timezone passed from client to server via cookie for SSR consistency.

**Out of scope:** Unit conversion.

**Already in place (E03-T01):** `src/lib/i18n/request.ts` returns only `locale` and `messages`; add `timeZone` (from the timezone cookie, validated with zod, falling back to `Europe/Vilnius`), `now` if needed and shared `formats` there, so the server and `NextIntlClientProvider` (which inherits them from the request config in `app/[locale]/layout.tsx`) agree. Reading a cookie makes pages dynamic (they are static now), so consider formatting user-specific times only in client components or accept dynamic rendering for the signed-in area. `UI_LABELS` (`src/components/ui/ui-labels.ts`, `TODO(E03-T03)`) still has English strings with hand-written plurals ("1 result" / "N results", "and N more") and is the first candidate for the ICU plural messages. Vitest renders components with real messages through `renderWithIntl()` (`tests/helpers/render-with-intl.tsx`, time zone fixed to `Europe/Vilnius`). For ICU argument type checking, next-intl's `experimental.createMessagesDeclaration` plugin option can generate literal message types.

**Acceptance criteria**
- [ ] LT plurals render correctly: "1 serija", "2 serijos", "10 serijų", "21 serija", "1,5" (decimals use "other").
- [ ] EN plurals: "1 set", "2 sets".
- [ ] Weights and dates follow the active locale in both server and client renders (no hydration mismatch warnings).
- [ ] Unit tests cover all presets in both locales.

**Depends on:** E03-T01

### E03-T04 · Missing-key check in CI — `S`
**Why:** It's easy to add an English string and forget the Lithuanian one; CI should catch it.

**Scope**
- Script `npm run i18n:check` that compares the key trees of `en.json` and `lt.json` and reports keys missing in either file, empty values, and ICU syntax errors.
- Added to the CI lint job.
- Short contributor note in the docs: how to add a new string.

**Out of scope:** Machine translation.

**Already in place (E03-T01):** `src/lib/i18n/messages.test.ts` already compares the key trees (flat, two levels: namespace → key), rejects empty values and the ASCII apostrophe (ICU quoting), and checks the feature namespaces exist; `MESSAGES` (`src/lib/i18n/messages.ts`) is typed against `en.json`, so a key missing in `lt.json` already fails `typecheck`. The script can reuse that logic for clearer output (file + key path) and add ICU syntax checks; `intl-messageformat` / `@formatjs/icu-messageformat-parser` are installed as next-intl dependencies (add the parser as a direct, pinned dev dependency rather than relying on the transitive one).

**Acceptance criteria**
- [ ] Adding a key only to `en.json` fails CI and the output lists the missing key path and file.
- [ ] An empty string value or broken ICU syntax (e.g. unclosed `{count, plural`) fails the check.
- [ ] The check runs in under 5 seconds.

**Depends on:** E03-T01, E01-T05

### E03-T05 · Translated catalog content — `S`
**Why:** Seeded tags and common exercises should appear in the user's language, while user-created names stay as they were typed.

**Scope**
- Tags show `label_lt` or `label_en` depending on the active locale.
- Seeded exercises and machines get Lithuanian names and descriptions via `exercise_translations` / `machine_translations` (decision Q2).
- Search (E06-T02) matches the original name and all translations.
- Display rule: show the translation for the active locale if it exists, otherwise the original name.

**Out of scope:** Users translating their own exercises.

**Acceptance criteria**
- [ ] With LT active, the "chest" tag shows as "Krūtinė"; with EN, "Chest".
- [ ] Searching "spaudimas" and "bench press" both find the seeded "Bench press".
- [ ] User-created exercises show their original name in both locales.
- [ ] Every seeded tag, machine and exercise has both EN and LT text (seed test).

**Depends on:** E06-T01
